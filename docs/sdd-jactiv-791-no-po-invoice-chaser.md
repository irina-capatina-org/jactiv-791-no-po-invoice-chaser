## 1. API Workflow Overview

The No-PO Invoice Chaser automates daily compliance monitoring for the Accounts Payable function, enforcing the no-PO-no-pay policy. Triggered by schedule at 10:00 AM Europe/Bucharest on weekdays, it queries Coupa via REST API for invoices dated within the past seven calendar days with status `draft` or `new`, excludes credit notes, and identifies those lacking a properly linked purchase order at the line level.

When qualifying invoices are found, a Slack Block Kit direct message is sent to Irina Capatina (member ID `WLX9BD8FN`) with the count and a filtered Coupa URL. On a clean day (count = 0), the run completes successfully without sending any notification (BR-07).

The workflow is read-only against Coupa; no invoice approval, PO creation, record modification or requester follow-up is performed (BR-10).

| Name | Type | Value | When |
|---|---|---|---|

| `slack_sent` | boolean | `false` | Count = 0 (no message sent per BR-07) or delivery failed |

## 4. Execution Flow

| Step | Activity | Input | Output | Rules |
|---|---|---|---|---|
| 1 | Initialize variables | Orchestrator trigger | `windowStart`, `windowEnd`, `runDate` | Scheduled: 10:00 AM Europe/Bucharest on weekdays |
| 2 | Compute date window | Current date | `windowStart` = today − 7; `windowEnd`, `runDate` = today | [DEFAULT] timezone via Orchestrator |
| 3 | Coupa HTTP GET | `status[in]=draft,new`; dates within window | Array of invoices | BR-04; connector auth via Integration Service |
| 4 | Filter invoices | Invoice array | Exclude credit notes (`is-credit-note`); exclude if line `po-number` absent | BR-01, BR-02, BR-03 |
| 5 | Count results | Filtered set | `qualifyingCount` = integer | BR-05 |
| 6 | Decision gate | `qualifyingCount` | If 0: skip to step 9; if > 0: continue | BR-07 |
| 7 | Build Coupa URL | `windowStart`, `windowEnd` | `coupaUrl` with query params | BR-06 |
| 8 | Slack HTTP POST | `qualifyingCount`, `coupaUrl`, dates | Block Kit message to member `WLX9BD8FN` | BR-06; `slack_sent = true` if HTTP 200 |
| 9 | Output & log | Count, send status | Return `status`, `qualifying_count`, `slack_sent` | Success / failed based on all steps |

## 6. Error Handling

| Failure | Detection | Response | Outcome |
|---|---|---|---|
| Coupa auth failure (invalid/expired cred) | HTTP 401/403 at step 3 | Log error; fail run | No Slack message sent (BR-09) |
| Coupa unavailable (5xx or timeout) | HTTP 5xx or timeout at step 3 | Log error; fail run | No Slack message sent (BR-09) |
| Slack delivery failure (API error) | Non-200 response at step 8 | Log error; fail run | Run recorded as failed; no retry (BR-08) |
| Missing or malformed invoice record | Expected field absent during step 4 filter | Log warning; skip record; continue to next | Continue processing (BR-08 — no abort on data anomaly) |
| Unhandled .NET exception | Any uncaught exception | Global exception handler logs details; fail run | No Slack message; recorded as failed |

No retry, fallback or recovery behavior. A run that cannot complete is recorded as failed (BR-08, BR-09).

## 8. Testing Strategy

### Happy Path
| Case | Input | Expected | Notes |
|---|---|---|---|
| Non-empty result | >0 invoices, no PO | Slack Block Kit DM posted with count and Coupa URL; slack_sent = true | Window dates in footer = run-date ± 7 days |
| Clean day | All invoices have PO | count = 0, no Slack POST, status = success, slack_sent = false | BR-07: no notification on zero |

### Business Exceptions
| Case | Trigger | Expected | Notes |
|---|---|---|---|
| B1: Credit note | `is-credit-note = true` | Excluded from count; exclusion logged; processing continues | At least one credit note in window |
| B2: Description-only PO | PO text in description, line-level field empty | Treated as no PO; included in count | Verify line-level check, not description |
| B3: Zero results | No invoices match status + date | No message sent; status = success | Condition = count 0, not query failure |

### System Errors
| Case | Trigger | Expected | Notes |
|---|---|---|---|
| S1: Coupa auth fail | Invalid credential | HTTP 401/403; run fails; no Slack sent | Test revoked credential |
| S2: Coupa unavailable | 5xx or timeout | Error logged; run fails; no Slack sent | Simulate service down |
| S4: Slack delivery fail | API error response | Run fails; error logged; no message sent | Invalid token scenario |
